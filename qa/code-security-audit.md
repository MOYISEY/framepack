# Framepack independent code/security audit

Date: 2026-10-02. Reviewer: delegated code/security agent, separate from implementation and the design/a11y reviewer. Reviewed `src/core.ts`, `src/export.ts`, `src/zip.worker.ts`, `src/main.tsx`, `src/demo.ts`, and `src/i18n.ts`. No product source changes, publishing, or credential access were performed by this reviewer.

Final result: **no open high- or medium-severity issue found in the reviewed workflow after fixes**. This is a scoped code and browser audit, not a claim that arbitrary devices cannot run out of memory or that browser image decoders have no vulnerabilities.

## Independently verified behavior

- **Resource preflight:** 20 files / 15 MiB each / 80 MiB inputs, 12,000,000 pixels and 8,192 px per side. A forged 5000 × 3000 PNG header is rejected with `large` before `createImageBitmap` is called (instrumented decoder call count: zero). Actual decode dimensions must match inspected oriented dimensions before drawing. Processing is sequential; bitmap closure and canvas reset are in a `finally` block. Retained responsive assets and ZIP staging are capped at 80 MiB. ZIP input and output buffers use transfer lists.
- **JPEG orientation:** independently generated four-quadrant JPEGs with EXIF orientations 1 through 8 were processed and decoded again. Every corner has the expected color for rotations and mirrors. All eight passed in Chromium and Playwright WebKit; this verifies pixels, not only width/height swaps.
- **Transparency and format:** PNG and WebP output retain alpha=0 in an originally transparent corner. JPEG output uses the explicitly selected white background and alpha=255. A monkey-patched Canvas encoder that returns PNG for requested WebP is rejected as `encoder`; it is not mislabeled as WebP. Output extension follows the selected, verified MIME.
- **Animation and metadata handling:** APNG `acTL`, WebP `ANIM`/`ANMF` and the VP8X animation flag are explicitly rejected. PNG eXIf and WebP EXIF are explicitly unsupported, avoiding unchecked orientation descriptors for those formats. GIF, SVG and HTML contents fail the accepted image signatures. Bounds checks constrain chunk and JPEG EXIF reads. Malformed extended WebP probes were rejected by the browser decoder rather than exported.
- **Filenames and HTML:** stems are normalized to bounded ASCII and use a queue-wide collision set; ZIP paths are fixed under `assets/`. Windows device basenames are prefixed. React escapes displayed original filenames; JSON serializes original names. Generated HTML escapes `&`, `<`, `>`, both quote types. An alt containing `"<img src=x onerror=alert(1)>&'` was exported as escaped text. No injected element appears in the generated markup.
- **Actual handoff ZIP:** browser download `audit-demo-pack.zip` is a real 133,914-byte ZIP. It was unpacked with fflate and each of its six WebP assets was decoded independently with sharp. Every actual byte count, width, height, format and srcset width descriptor matches the manifest. The asset byte sum also matches `manifest.assetsBytes`; the native 400 px width of the rotated sample emits only one variant.
- **Cancellation and retry:** with delayed Canvas encoding, Cancel marks all three queued images cancelled. Retrying the first row completes that row while the other two remain cancelled. Busy guards prevent concurrent queue mutation, recipe changes, and exports.
- **URL cleanup:** instrumentation records five active image object URLs after building the three-image demo (three thumbnails, one source, one selected result). After Clear queue, all image URLs are revoked; only the generated ZIP URL remains during its documented ten-second download lifetime. Selection and recipe cleanup use effects and explicit revocation.
- **Byte reporting:** variant saving is `(originalBytes - variantBytes) / originalBytes`, so larger variants produce negative savings / visible growth. Set totals use originals of ready images as the denominator, and the UI labels that comparison separately from per-variant comparisons. ZIP size is reported separately. No automatic target KB guarantee is advertised.
- **Privacy:** reviewed runtime code has no image upload, analytics, credentials, paid API, remote-font loading, or source persistence path. Only language/theme preferences are written to localStorage. Originals remain in File references for this session and are never put in the ZIP. Export documentation explicitly acknowledges possible color-profile and metadata changes and does not claim forensic sanitization.

## Final hardening review

The latest `core.ts`, `export.ts`, `zip.worker.ts` and the remaining-budget call in `main.tsx` were independently reviewed again after the implementation changes. **No new high- or medium-severity issue was found.**

- PNG now requires the initial IHDR chunk's exact 13-byte length. A malformed length is rejected as `corrupt`.
- WebP now checks every VP8X, VP8 and VP8L dimension against the accepted dimensions and the resource limits. A synthetic VP8X/VP8 dimension mismatch is rejected as `corrupt` before decode.
- JPEG now rejects repeated SOF markers and checks the first SOF dimensions immediately. A two-SOF probe is rejected as `corrupt`.
- `processImage` receives the queue's remaining byte budget. It checks accumulated bytes after each encoded variant, before retaining the variant or continuing the width loop. With a one-byte budget, a three-width request stops after only two encoder calls: one preview and one variant, then `output`. An individual encoding operation still needs to finish before its actual Blob size can be checked.
- `readBlob` uses FileReader with load/error/abort handlers and removes its AbortSignal listener on completion. A 64 MiB active read and a pre-aborted read both reject with `AbortError`; normal FileReader-backed image processing and ZIP staging passed the production UI handoff rerun.
- The production bundle embeds the ZIP worker source as an inline Blob/data worker, so there is no separate worker asset to fetch. Its termination and transfer-list behavior remain intact. An immediate cancel during worker creation returned the UI to Download ZIP; a subsequent fetch of the captured worker Blob URL failed, confirming revocation in that run.
- The production UI handoff was rerun after these changes. All six decoded assets, manifest bytes/dimensions/MIMEs, HTML escaping, cancellation/retry, original preview and active URL cleanup passed again. The UI probe checks actual Blob URL reachability because the inline worker can revoke its URL from its own realm.

New direct browser evidence: `final-core-probe-results.json` (`pass: true`). Run `node qa/final-core-probe.mjs`; it transpiles the reviewed core with the installed TypeScript compiler and executes it in Chromium through a data module, without requiring Vite. The final UI rerun used `npm run preview -- --port 4175 --configLoader native` and `node qa/audit-ui-probe.mjs` against the built production bundle. Full dev-server repro can require the main agent's approved environment when esbuild dependency re-optimization is blocked by the filesystem sandbox.

## Scope and remaining limits

The audit browser runs cover Chromium 153 and the installed Playwright WebKit build on Windows. **Actual Safari was not tested.** The Firefox audit probe could not create a page in this sandbox (`browser.newPage` raised `Cannot read properties of undefined (reading '_page')`); therefore this reviewer makes no Firefox pass claim. The main agent's separate E2E matrix, live deployment, dependency audit and offline checks are outside this independent review.

Cancel for image decoding/Canvas encoding takes effect between browser API operations; those native operations are not preempted. ZIP assembly is now preemptible through Worker termination. The resource limits bound intended allocations but do not guarantee success on memory-constrained hardware. PNG/WebP with EXIF and animated PNG/WebP remain intentionally unsupported. Empty alt text is exported verbatim as decorative and must be supplied manually for meaningful images. `sizes` needs adaptation to the receiving site's CSS layout. Browser re-encoding may alter profiles and metadata; original files are neither modified nor claimed to be forensically scrubbed.

Canvas may return PNG when the requested encoder is unsupported; the implementation's strict MIME check is consistent with [MDN toBlob documentation](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob). Intrinsic encoded widths are required for `w` descriptors; the manifest/decoded-pixel checks follow [MDN responsive image guidance](https://developer.mozilla.org/en-US/docs/Web/HTML/Guides/Responsive_images).
